# 251 M11 Slice: Compiler-Backed LSP Diagnostics

This chapter documents wiring `sec4audit-language-server` diagnostics to real `sec4-core` parse + semantic analysis.

## What it is

Updated:
- `compiler/sec4-lsp/Cargo.toml`
- `compiler/sec4-lsp/src/main.rs`
- `Cargo.lock`

Key changes:
- LSP now handles:
  - `textDocument/didOpen`
  - `textDocument/didChange` (full sync)
  - `textDocument/didClose`
- diagnostics are generated by:
  - `sec4_core::parse_source`
  - `sec4_core::analyze_program`
- server publishes:
  - `textDocument/publishDiagnostics` notifications,
  - clear diagnostics on close/change-to-valid state.

## Why it exists

Previous LSP bootstrap only negotiated initialize/shutdown and returned method-not-found for real editor events. That prevented red squiggles and blocked practical editor integration.

## How it works internally

1. Maintain an in-memory document map keyed by URI.
2. On `didOpen` and `didChange`:
   - parse URI to file path,
   - run parser + semantic analysis on current text,
   - map compiler diagnostics to LSP diagnostics and publish.
3. On `didClose`:
   - remove document from state,
   - publish empty diagnostics for that URI.
4. Unknown request methods still return method-not-found for request/response flows.

## Inputs, outputs, and constraints

- Inputs:
  - JSON-RPC messages over stdio.
- Outputs:
  - LSP responses + diagnostics notifications.
- Constraints:
  - URI diagnostics currently support `file://` documents.

## Failure modes and diagnostics

- unsupported/non-file URI -> published LSP diagnostic (`L9001`) for editor visibility.
- invalid didOpen/didChange/didClose payload with request id -> invalid-request response.

## Tests added/updated

`compiler/sec4-lsp` unit tests now cover:
- initialize/shutdown capability negotiation,
- didOpen diagnostics publication,
- didChange diagnostics clearing when source becomes valid,
- didClose diagnostics clearing,
- method-not-found behavior for unsupported requests.

## Tradeoffs and next steps

- Tradeoff:
  - diagnostics are currently per-document and non-incremental (full text re-analysis on each change).
- Next:
  - add `textDocument/definition` and `textDocument/hover` using compiler symbol/type data,
  - add bounded analysis budgets and partial-result behavior for larger files/workspaces.
